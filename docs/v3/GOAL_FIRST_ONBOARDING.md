## 用户看到的变化

创建页只需要“学习目标”和“已有基础”；基础可不填，也可写零基础/不确定。时间放在可选设置内。学科、主题、范围及评价方式由AI整理，随后显示计划预览。用户可以一句话调整计划，确认后进入学习，不再填写“本次确认的范围”或选择学习模式。

侧栏移除V2历史入口，旧浏览器保存的V2选择不会重新打开旧页面。旧数据不删除；原只读适配API和匹配旧环境恢复能力保留。旧版未完成创建请求先查询结果，不能把旧请求身份直接换成新格式重放。

资料在创建记录后可选导入，支持现有粘贴、UTF-8 TXT/Markdown。

- 没有教学资料：AI先限定起步范围，再整理简短讲义，服务端存为有版本和行号的普通教学来源，明确标记“AI生成，未经独立来源核验”，不冒充官方资料。
- 有教学资料：范围与计划围绕实际上传内容，不再自动生成替代讲义；先前的AI讲义不会混入这次规划依据。
- 目标依赖具体内部制度、公司政策等而缺文件：明确等待资料，不生成这些规定。文件缺少的内容应回答未规定，不能按其它企业惯例补全。
- 只有私有答案：不能拿它当教学资料；私有文件仍需在计划确认时显式选择适用节点，仅供出题和评分，不能进入范围整理或Tutor。
- 需要尚未支持的实际评价能力：说明边界，允许调整目标，不假装已经完成实际听说、实验或程序执行。

“模式合并”指单一用户入口，后端仍保留能力、来源和通过守卫。旧探索项目继续遵守原限制；新流程可进行文字教学与练习，练习通过不代表官方认证，也不意味着AI整理内容已获独立事实核验。

## API 与兼容性

新建可发送：

```json
{
  "request_id": "11111111-1111-4111-8111-111111111111",
  "intent": {
    "goal": "从零学习Python，先能读懂简单短代码",
    "prior_knowledge": "零基础",
    "time_budget_minutes": 120,
    "session_minutes": 30
  }
}
```

已有调用方的完整profile格式继续兼容；profile和intent只能选一个。创建本身和GET不运行模型。前端继续使用原有confirm_profile操作发起AI准备；上传后使用replan重新准备，confirm_plan冻结，begin开始教学。原pending_input_id、draft_revision、request_id及retry_token校验保持。

新增guided_projects是仅在显式创建时建立的可选功能表，flow_version=guided-1；GET只检查其是否存在，不初始化或升级旧库。创建记录与功能标识同事务提交，重放同一创建不产生第二个项目。旧项目不加该标识，保留原准备和Checkpoint路径。project/thread身份不变，无需重写旧Checkpoint。

公开视图新增guided、learning_basis与preparation_notice，仅表示入口、来源与当前说明，不提供完整内部任务数据。learning_basis区分ai_generated、provided_material、requires_material、unsupported；不是新的学习模式选择框。

## 请求、保存与恢复

复用model_tasks持久化预算：scope、notes、guided_plan分别最多3次请求，网络重试和输出修复受原1次限制；共享单操作12次预占，模型timeout45秒、SDK重试0不改。有教学资料时不运行notes任务。

范围、生成讲义和候选计划各自缓存有效结果；讲义导入请求与来源身份稳定，范围应用保存request_id。真实进程退出后，旧结果复用且原请求计数不清零。普通技术恢复沿用旧任务；确定已耗尽或连续非法的AI任务停下来，返回可编辑等待页，由用户明确发起新准备，原失败任务和收费计数保留，不暗中再修第三次。

资料变化仍递增draft_revision、使旧确认失效。上传资料优先时过滤以前AI讲义，保留其旧版本记录。正式学习后继续冻结来源、策略和评价器，资料不能添加工具、取消上限或改写通过门槛。
