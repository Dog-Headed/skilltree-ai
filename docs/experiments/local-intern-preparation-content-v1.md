# 本地 Intern-S2 前两步内容结构实验

日期：2026-10-28。**实验未达到启用条件，保持 `legacy` 默认。不要把出题实验的 7.5 秒结果套用到这里。**

本实验接续本地 `c5c41fa` 出题实验；未推送 GitHub，也未部署生产服务器。现有出题内容契约不受此实验开关影响。

## 为什么要分别测量

一次 `confirm_profile` 请求依次执行范围整理、可选的整树资料生成和 Planner。三个阶段共享上层操作预算，各自保留三次请求、一次网络重试和一次输出修复上限。120 秒是传输超时设置，不是固定等待时长；流式读取的超时也不是整个工作流的总时间保证。

第一步 `LearningPreparation` 原本只有学科、树名、范围、能力选择、依据分类和说明，主要已经是内容。没有类似出题的大量项目身份、冻结快照或评价器版本可移走。最后保留原业务结构及提示：有上传资料时，只从送给范围模型的目录中移除已在程序里核验的身份、版本和哈希等冗余信息，保留完整正文与可用的来源说明。没有上传资料时，新旧模式模型请求相同，单元测试验证此点。

第二步 `StudyNotes` 原本只有一个 Markdown 字符串。试验把每个确认分支的定义规则、例子、误解和练习方向交给模型填写，程序管理分支顺序、标题与格式，最后仍校验原 `StudyNotes` 100～6000 字符契约，不截断或丢弃分支。

## 尝试和结果

1. 嵌套对象：SQL、数学反复漏掉最外层右括号；补充闭合提示后仍发生，均严格拒收。
2. 扁平命名字段：一组 SQL 由旧格式 56.032 秒降至 35.796 秒并首次通过；但数学出现重复分支字段和未转义引号，预算内仍失败。独立 SQL API 串联曾成功，但含两次输出修复，耗时 258.844 秒，10 节点为直线；不能当作性能或分支图验收成功。
3. 最终候选使用位置数组：顶层 `sections`，各分支按已确认顺序各返回四段字符串，程序管理全部编号和字段映射。最终配对结果如下。

| 资料样本 | 原格式 | 最终实验格式 |
|---|---:|---:|
| SQL，7 分支 | 33.704 秒，首次通过 | 67.812 秒，两次请求后失败 |
| 数学，6 分支 | 68.360 秒，首次通过 | 46.094 秒，首次通过 |

最终实验格式只通过 1/2，原格式通过 2/2。SQL 失败包含数组形状不符；未将失败耗时记为成功提速。随后独立全流程 API 验收的范围阶段首次通过，资料阶段经一次修复仍失败，项目正确停留在可编辑档案状态，没有冻结或伪造路线。

最初并行试验有一个未获得结果的 Python 案例，停止进程后保留已完成样本，未计为通过。后续采用单工作线程。流式 API 未返回 Token 用量的字段按未知记录，没有填零或估算。有限样本也不足以评估全部教学事实质量。

## 校验与状态保护

- 不放宽字段、资料长度、能力和业务校验，不忽略多余字段，不补造模型内容。
- 分支数量、每分支四部分、字符串类型、内容长度及非空检查继续执行。
- 已保存的任务仍使用原公开结果类型和持久化预算，断点恢复复用已完成结果；GET 不调用模型。
- 新增内容 JSON 重复字段会给修复请求提供安全的字段路径，避免仅返回笼统错误。
- 完整回归曾通过 1034 项（两个既有 websockets 弃用警告）；最终位置数组及重复字段诊断修改后，91 项受影响专项回归通过。离线测试通过不等于书生在线输出通过。
- 在线测试使用自编目标及新建独立数据库，没有写入生产课程；本地 `.env` 未启用新的准备阶段开关。

## 复现和开关

脚本只在显式 `--live` 时调用已配置的真实 Intern-S2，不允许自动换用其他模型；会消耗现有 API 配额。默认单工作线程，输出目录必须不存在。

```powershell
python scripts/benchmark_preparation_content.py --live --stage notes --case sql --case arithmetic
```

手动实验才可指定 `SKILLTREE_PREPARATION_GENERATION=content-v1` 并重启本地 `app.py`；当前**不建议启用**。省略开关或设置 `legacy` 即使用原实现。`SKILLTREE_QUIZ_GENERATION` 是单独的出题开关。

证据保留在 `work/local-preparation-content-positional-20261028`、`work/local-preparation-positional-live-20261028`，以及早期试验目录 `local-preparation-content-pilot-20261028`、`local-preparation-content-closure-20261028`、`local-preparation-content-flat-20261028`、`local-preparation-flat-diagnostics-20261028` 和 `local-preparation-flat-live-20261028`。

当前结论是：还不能可靠地将前两步提速。后续应先解决提供方的结构输出可靠性和长内容成本，再比较完整成功耗时；不得通过减少树的主要分支、删除校验或无限重试来制造改善。
